Rikugan 2.0 is a rewrite. The Python plugin is gone: Rikugan is now a native C++ plugin for IDA Pro 9.3 and Binary
Ninja, on Linux, macOS and Windows, with its agent built on [libomc](https://github.com/buzzer-re/Oh-My-C) and linked
in-process. It keeps what Rikugan was for (an agent that lives inside your disassembler and works on your database)
and changes almost everything around it.

## What's new

**Any model.** Sign in with a subscription you already pay for (Claude, ChatGPT/Codex, Gemini, GitHub Copilot and
dozens more), paste an API key, or point it at a local server (Ollama, LM Studio, llama.cpp, any OpenAI-compatible
endpoint). Connect a model is the first thing a new install shows, and no restart is needed. Claude Code and Codex
logins on the same machine can be shared after you confirm. Ctrl+M switches model and thinking level at any time.

**The panel.** Every turn is a timeline: thinking, each tool call with its result, addresses and symbols you click to
jump there, subagents with their live progress, and permission, approval and plan cards. The strip above it shows what
Rikugan is doing, its todo list and the `/goal` it works toward. Ctrl+K opens every command, Ctrl+J the agents (with
Steer and Stop). Chats are named after their first exchange. Colours follow the host's theme.

**60+ native tools** for navigation, the decompiler, disassembly, cross-references, strings, types, annotations,
scripting and Binary Ninja IL / Hex-Rays microcode, called in parallel where it is safe. Rikugan can also read, write
and edit files, run shell commands and search the web, each kind asking the first time in a chat.

**Changes you control.** Renames, types, comments and patches can ask before they land (once or for the whole chat).
Every reversible change keeps its own Undo, and `/undo` takes back the last ones.

**Modes.** `/plan` writes a read-only plan you can edit before it runs. `/explore` investigates and ranks its findings.
`/modify` explores, plans and patches, then asks whether to keep the patches. `/research` writes linked notes next to the
database.

**Goals.** `/goal <objective>` keeps Rikugan working on its own, turn after turn, until it has checked that the
objective is met: recover a struct and type everything that uses it, name a whole subsystem, map a protocol. The strip
shows the goal and its time, with Pause and Clear, and database changes still ask first unless you allowed them for
the chat.

**Subagents.** Rikugan splits work across isolated agents that run in parallel, each in its own context, and you can
follow, steer or stop each one. `/btw` asks a side question while a run goes on.

**Several databases.** In Binary Ninja, Rikugan can open another file in a new tab (after you agree) and ask it
questions, to compare two builds or look something up in a library. The full-window view puts the chat in a tab with
every open database's chats beside it.

**More.** Images pasted or dropped into the message. Persistent memory in `RIKUGAN.md` next to the database. 12 built-in
skills plus your own. MCP servers, and Binary Ninja's own MCP server with one button. A bulk renamer that names every
function in batches on parallel workers. Profiles with IOC filters and tool limits that apply to every tool result.
Right-click actions in both hosts (Explain this, Rename with Rikugan, Deobfuscate, Find vulnerabilities ...). Crash logs
in `~/.rikugan/logs/`, with a recovery copy of every open database.

**Updates.** Rikugan checks for a newer release once a day and installs it when you say so: the package for your host
and platform, checked against its SHA-256 and its version, takes the plugin's place and the host uses it after a
restart. Settings › Behavior › Updates turns the check off.

## Upgrading from 1.x

Run the installer below. It moves a Rikugan 1.x (Python) install of the same host to `~/.rikugan-1.x-backup/` before
it installs 2.0. Rikugan 1.x never checks for updates, so this one install is by hand. Chats and settings from 1.x are
not migrated: connect a model again from the panel.

Gone with the Python version: Rikugan's own provider layer (libomc covers far more providers and logins), encrypted API
keys (credentials live in `~/.rikugan/omc/agent/auth.json`, mode 0600 on Linux and macOS), importing Claude Code and
Codex skills and MCP servers, the research-note reviewer chain, resuming a cancelled mode, skill `allowed_tools`, and
undo of file writes.
